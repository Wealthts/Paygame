# GamePay UX/UI — ต้นแบบที่กดลองได้

## เปิดใช้งาน

ดับเบิลคลิก `index.html` เพื่อเปิดใน Chrome หรือ Edge ได้ทันที ไม่ต้องลงโปรแกรมเพิ่ม ไม่ต้องติดตั้ง framework และไม่ต้องรัน server

บนคอมพิวเตอร์มีเมนูซ้ายให้เลือกดูทั้ง 10 หน้าจอ ส่วนมือถือจะแสดงเฉพาะตัวแอป

## ไฟล์ที่ใช้แก้ไข

- `index.html` — โครงพื้นที่แสดงต้นแบบ
- `style.css` — สี ฟอนต์ ขนาด ระยะห่าง และรูปแบบหน้าจอ แบ่งหัวข้อไว้ในไฟล์
- `data.js` — ข้อมูลเกม ข้อมูลเริ่มต้น และรายชื่อหน้าจอ
- `helpers.js` — ตัวช่วยจัดรูปแบบข้อมูลและแสดงข้อความ
- `components.js` — ชิ้นส่วนที่ใช้ร่วมกัน เช่น ไอคอน ปุ่ม และเมนู
- `games.js` — หน้าแรก รายการเกม แพ็กเกจ และตรวจ UID
- `payment.js` — คำนวณยอด หน้าชำระเงิน และผลชำระเงินจำลอง
- `history.js` — หน้าประวัติ รายละเอียดคำสั่งซื้อ และชำระต่อ
- `auth.js` — หน้าโปรไฟล์ เข้าสู่ระบบ และสมัครสมาชิก
- `admin.js` — หน้าผู้ดูแล คำสั่งซื้อ แพ็กเกจ และปรับแต้ม
- `app.js` — เริ่มต้นแอปและเปลี่ยนหน้าจอ โหลดไฟล์นี้เป็นลำดับสุดท้าย
- `events.js` — รับการกดปุ่ม การกรอกข้อมูล และส่งฟอร์ม
- `fonts/` — ฟอนต์ Noto Sans Thai พร้อมใบอนุญาต OFL เก็บไว้ในเครื่องเพื่อเปิดแบบออฟไลน์ได้

การแก้ที่พบบ่อย:

1. เปลี่ยนสี: แก้ `--red`, `--gold`, `--bg` ใน `style.css`
2. เปลี่ยนชื่อเกมหรือราคา: แก้รายการ `games` ใน `data.js` โดย `packs` เก็บ `[จำนวนหน่วย, ราคา]`
3. เปลี่ยนชื่อผู้ใช้หรือแต้มเริ่มต้น: แก้ `state.user` และ `state.points` ใน `data.js`
4. แก้ข้อความแต่ละหน้า: หา `homePage`, `packagePage`, `checkoutPage` เป็นต้น
5. เปลี่ยนอัตราส่วนลดหรือค่าธรรมเนียม: ดูฟังก์ชัน `totals()` ใน `payment.js` และแก้ข้อความที่แสดงให้ตรงกันด้วย

## หน้าจอ

หน้าแรก, เลือกแพ็กเกจและ UID, ตรวจสอบและชำระเงิน, ประวัติ, โปรไฟล์, เข้าสู่ระบบ, สมัครสมาชิก, แอดมินคำสั่งซื้อ, แอดมินแพ็กเกจ, แอดมินผู้ใช้และแต้ม

ยึดสเก็ตช์ใน PDF โดยยังไม่ทำหน้าสะสมแต้มและใบเสร็จตามคำขอ แต่คงปุ่มแต้ม/แลกรางวัลไว้ และมีปุ่มบันทึกใบเสร็จในกล่องชำระสำเร็จและรายละเอียดรายการที่สำเร็จ กดแล้วแจ้งว่าหน้าปลายทางยังไม่รวมในต้นแบบ ไม่มีการดาวน์โหลดจริง

เพิ่มหน้าที่มีเมนูแต่ยังไม่มีแบบ: โปรไฟล์และผู้ใช้/แต้มของแอดมิน หลังชำระสำเร็จจะแสดงกล่องยืนยันแล้วกลับหน้าประวัติ

## ลองกดตามนี้

1. เริ่มต้นด้วย 0 แต้มและประวัติว่าง
2. เลือก RoV → 400 คูปอง → กรอก UID 1234567890
3. ยอดชำระ ฿350 และตัวเลือกใช้แต้มถูกปิดไว้จนมีครบ 100 แต้ม
4. จำลองชำระสำเร็จ → ได้ 35 แต้ม และเพิ่มคำสั่งซื้อในประวัติอัตโนมัติ
5. ปุ่มแต้ม/แลกรางวัลและบันทึกใบเสร็จยังอยู่ แต่ยังไม่มีหน้าปลายทาง

แถบสถานะด้านบนถูกนำออก รายการเกมใช้การ์ดสีแบบเดิม โดยไม่มีลายเหลี่ยมด้านใน

## ขอบเขตต้นแบบ

- ทุกอย่างเป็นข้อมูลจำลองในหน่วยความจำ รีเฟรชแล้วเริ่มใหม่ ไม่เชื่อมต่อฐานข้อมูล
- ไม่มีระบบ login/JWT หรือการแบ่งสิทธิ์จริง ฟอร์มเข้าสู่ระบบและสมัครสมาชิกใช้ทดสอบ UX เท่านั้น ไม่มีการส่งหรือเก็บรหัสผ่าน
- การชำระเงินไม่มี QR ที่รับเงินจริง และไม่ขอข้อมูลบัตร
- ชื่อเกม ราคา UID และค่าธรรมเนียมเป็นตัวอย่างจากสเก็ตช์ ไม่ใช่ข้อมูลที่ยืนยันกับผู้ให้บริการ
- การปิดแพ็กเกจและการปรับแต้มมีผลเฉพาะการทดลองครั้งนั้น
- ไม่รวมหน้าสะสมแต้ม การแลกรางวัล และใบเสร็จ ตัวเลือกใช้แต้มลดราคาในหน้าชำระเงินยังคงอยู่
- โปรโมชัน ×2 และระดับสมาชิกเป็นหน้าตาตัวอย่าง ยังไม่มีระบบแคมเปญหรือการเลื่อนระดับ
- ฟังก์ชันส่งอีเมลรีเซ็ตรหัสผ่านและช่องทางช่วยเหลือแสดงสถานะตัวอย่าง

## เรื่องที่ต้องตกลงก่อนเชื่อม Backend

ใน PDF ใช้ 100 แต้ม = ฿10 แต่ `database/README.md` เสนอ 1 แต้ม = ฿1 ต้นแบบนี้ยึด PDF และไม่ได้แก้ฐานข้อมูลเดิม

แต้มที่ได้รับในต้นแบบคิดจากราคาแพ็กเกจหลังหักส่วนลด ไม่รวมค่าธรรมเนียม: `floor((price - discount) / 10)` ต้องยืนยันกติกากับทีมก่อนใช้งานจริง

UID ใช้กฎตัวเลข 10–12 หลักเหมือนกันเพื่อทดสอบหน้าจอ ระบบจริงต้องอ่านกฎของแต่ละเกมจาก Backend รวมถึงกรณี Riot ID/เซิร์ฟเวอร์

ต้องกำหนดเพิ่มเติม: วันสิ้นสุดแคมเปญ ×2, แต้มสมัครสมาชิก, เกณฑ์ระดับสมาชิกจากยอดสะสมตลอดชีพหรือยอดปัจจุบัน, การใช้คูปอง, ภาษี/ค่าธรรมเนียม และสถานะหลังชำระแต่ยังเติมไม่สำเร็จ

## แนวทางการออกแบบ

คงเอกลักษณ์แดง–ทองจาก PDF ใช้แดงกับปุ่มหลักและราคาที่ต้องสนใจ ใช้ทองกับแต้มและรางวัล ลดพื้นที่สีแดงขนาดใหญ่เพื่อให้ฟอร์มอ่านสบาย แยกสถานะด้วยข้อความร่วมกับสี และแสดงยอดสุทธิก่อนยืนยันเสมอ

หน้าเลือกรายการเกมใช้การ์ดสีไล่ระดับ พร้อมตัวอักษร ชื่อเกม และหมวดหมู่ โดยไม่มีลายเหลี่ยมตกแต่งด้านใน

## การโหลด JavaScript

ใช้ไฟล์ JavaScript ธรรมดาและ `defer` ตามลำดับใน `index.html` จึงดับเบิลคลิกเปิดไฟล์ได้เหมือนเดิม ไม่ต้องใช้ npm หรือ import/export อย่าสลับลำดับ script: โหลด data และตัวช่วยก่อน ส่วน app.js อยู่ท้ายสุด การรับฟอร์มล็อกอิน/สมัครสมาชิกอยู่ใน events.js และเรียกหน้าจอจาก auth.js
